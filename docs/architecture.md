# 아키텍처 결정 기록

## ADR-001: 프로토콜과 Windows 마운트 계층 분리

- 상태: 승인
- 날짜: 2026-08-26

SFTP, WebDAV, FTP/FTPS 구현은 `internal/vfs.Backend`를 구현한다. Windows
마운트 코드는 이 인터페이스만 사용한다. 프로토콜별 제약은 공통 계층에서
숨기지 않고, 지원하지 않는 연산으로 명확하게 반환한다.

이 경계는 다음 목적을 가진다.

- SFTP로 WinFsp 동작을 먼저 검증한 뒤 다른 프로토콜을 추가한다.
- 네트워크 I/O 없이 VFS 및 마운트 동작을 테스트할 수 있게 한다.
- 마운트 라이브러리 선택이 프로토콜 구현 전체에 번지지 않게 한다.

## ADR-002: WinFsp Go 연동 라이브러리

- 상태: 승인
- 날짜: 2026-08-26

Windows 전용 프로젝트이며 Windows 파일 API 의미 보존이 중요하므로
`github.com/winfsp/go-winfsp`의 네이티브 API를 사용한다.
`github.com/winfsp/cgofuse`는 현재 구현 후보에서 제외하고, 확정한 방식으로
해결할 수 없는 호환성 문제가 발견될 때만 다시 검토한다.

0.1 단계에서 메모리 백엔드와 실제 SFTP 백엔드로 다음 항목을 검증했다.

- 빌드 및 WinFsp 런타임 배포 방식
- 파일 생성, 열기, 덮어쓰기, 삭제, 이름 변경
- 한글과 공백이 포함된 파일·폴더 생성
- 파일 읽기·쓰기·삭제·이름 변경·이동
- Windows 탐색기와 메모장의 실제 읽기·저장
- SFTP 경로의 대소문자 구분

Windows 10/11 실제 환경에서 WinFsp 런타임 설치, 드라이브 문자 마운트와
기본 파일 작업을 확인했으며 마운트 실행 중 오류가 발생하지 않았다.

## 데이터 안정성 원칙

쓰기 완료와 서버 반영 성공을 분리하지 않는다. 서버 반영 전 로컬 임시
데이터를 삭제하지 않으며, 장시간 write-back cache는 1.0 필수 범위에서
제외한다. 자격 증명 값은 프로필 구조나 일반 설정 파일에 저장하지 않는다.

## ADR-003: WebDAV 전체 파일 PUT과 로컬 스테이징

- 상태: 승인
- 날짜: 2026-08-26

WebDAV 기본 쓰기는 HTTP `PUT`의 전체 파일 전송 방식이다. VFS의 임의 위치
쓰기 계약을 유지하기 위해 WebDAV 쓰기 핸들은 임시 파일에 변경 내용을 모은
뒤 `Sync` 또는 `Close`에서 전체 파일을 `PUT`한다. Windows 마운트 계층의
관리 캐시와 함께 사용할 때 원격 반영 실패 시 원본 스테이징 파일은 마운트
계층에 남아 재시도를 허용한다.

프로토콜 구현은 외부 WebDAV 클라이언트 라이브러리 대신 Go 표준 HTTP/XML을
사용한다. `PROPFIND`, `MKCOL`, `MOVE`, `LOCK`처럼 서버별 차이를 확인해야 하는
요청과 응답을 직접 검증하고, 지원하지 않는 속성 연산을 성공으로 가장하지
않기 위해서다.

## ADR-004: FTP/FTPS 클라이언트와 연결 직렬화

- 상태: 승인
- 날짜: 2026-08-27

FTP, Explicit FTPS와 Implicit FTPS에는 `github.com/jlaffaye/ftp`를 사용한다.
일반 FTP와 두 FTPS 연결 방식, 수동형 데이터 연결, MLSD/MLST와 UTF-8 처리를
직접 구현하는 대신 검증된 프로토콜 구현을 사용한다.

FTP 제어 연결 하나는 동시에 여러 명령이나 데이터 전송을 처리할 수 없다.
백엔드는 제어 명령과 데이터 전송 종료까지 연결을 직렬화한다. 연결·목록·읽기를
먼저 분리 검증한 뒤 같은 직렬화 경계 안에 쓰기 연산을 추가한다.

VFS의 임의 위치 쓰기는 로컬 임시 파일에 모은 뒤 `Sync` 또는 `Close`에서
`STOR`로 전체 파일을 반영한다. 서버 반영이 실패하면 호출자에게 오류를 반환하고
마운트 계층이 관리하는 원본 스테이징 데이터를 유지해 재시도를 허용한다.

## ADR-005: 0.5 Windows 데스크톱과 연결 수명

- 상태: 첫 구현, 실환경 검증 대기
- 날짜: 2026-08-27

추가 GUI 런타임 없이 Win32 기본 컨트롤과 Shell 알림 아이콘을 사용한다.
UI는 하나의 OS 스레드에서 소유하고, 연결/해제는 작업 goroutine에서 실행한 뒤
창 메시지로 결과를 전달한다. 첫 구현의 UI 작업은 한 번에 하나씩 실행하지만,
성공한 여러 마운트는 같은 프로세스에서 동시에 유지한다. 드라이브 문자와
연결 ID는 연결을 시작하기 전에 예약하며, 개별 연결 실패가 다른 연결을 종료하지 않는다.

프로토콜 CLI를 subprocess로 실행하지 않고 기존 백엔드와 WinFsp 어댑터를
직접 재사용한다. 비밀값을 명령행·환경변수로 전달하지 않는다. SFTP의
known_hosts 검증과 기존 메타데이터 어댑터를 유지한다. TLS 검증은 기본 활성화다.

설정은 사용자 설정 디렉터리의 `DKDrive/settings.json`에 저장한다. 선택한
비밀값만 현재 사용자 DPAPI로 보호하며, 복호화 실패 시 평문 저장으로 대체하지
않는다. 버전/형식/중복 드라이브를 검사하고, 같은 디렉터리의 임시 파일을
완전히 쓰고 동기화한 다음 교체한다. 읽을 수 없는 기존 설정을 자동 초기화하지 않는다.

GUI 마운트에는 별도 수명 보호 래퍼를 추가했다. 파일/폴더 핸들이 하나라도
열려 있으면 해제를 거부한다. 닫힌 핸들의 업로드/닫기 실패도 기억해 조용히
종료하지 않고 캐시 경로와 오류를 알린다. 정상 해제는 새 경로 작업을 차단한 뒤
WinFsp를 종료하고 백엔드를 닫는다. 일반 해제 실패 시 UI 스레드에서 실패한 연결별
강제 해제 확인을 받는다. 기본 선택은 취소이며, 확인 중에도 관리 작업은 잠근다.
승인하면 열린 스테이징 파일을 추가 업로드·삭제 없이 로컬 동기화·닫기한 뒤 WinFsp와
백엔드를 종료한다. 기존 업로드 실패 캐시도 보존한다. 새 연결에 자동 재업로드하지
않으며 응용 프로그램/Windows 버퍼의 미전달 데이터는 보장하지 않는다. 진행 중인
작업은 잠금 반환을 기다릴 수 있다. 기존 CLI의 종료 동작은 변경하지 않았다.

Windows 로그인 시 실행은 사용자가 선택한 경우에만 HKCU Run의 DKDrive
값을 등록한다. 연결별 AutoConnect와 독립적이며 기본 등록은 하지 않는다.
트레이 실패 시 창을 유지하고, 프로그램의 명시적 종료는 모든 연결이 일반 해제 또는
사용자 승인 강제 해제로 해제된 경우에만 완료한다. 취소/실패한 연결이 있으면
프로그램을 유지한다. OS 로그오프 처리에는 강제 해제 확인을 추가하지 않았으며,
OS 강제 종료·전원 차단에 대한 보장은 하지 않는다.

## ADR-006: 보존 캐시와 복구 메타데이터

- 상태: 첫 구현
- 날짜: 2026-09-01

업로드 실패 또는 사용자 승인 강제 해제로 스테이징 파일을 남길 때 같은 캐시
폴더에 버전이 있는 JSON 메타데이터를 원자적으로 기록한다. 프로필 ID·표시 이름·
프로토콜, 원격·로컬 경로, 크기·시각, 보존 사유와 마지막 오류만 기록하며 비밀번호,
Passphrase, 개인키 내용과 인증 헤더는 기록하지 않는다.

시작 시 캐시를 읽기 전용으로 검사해 정상 보존 항목, 기존 메타데이터 없는
`staging-*`, 파일 없는 메타데이터와 손상·조작된 메타데이터를 구분한다. 캐시 루트
밖의 경로와 심볼릭 링크는 복구 대상으로 신뢰하지 않는다. 이 단계에서는 항목을
자동 삭제하거나 원격 서버에 자동 재전송하지 않는다.
