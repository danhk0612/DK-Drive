# 아키텍처 결정 기록

## ADR-001: 프로토콜과 Windows 마운트 계층 분리

- 상태: 승인
- 날짜: 2026-08-26

SFTP, WebDAV, FTP/FTPS 구현은 `internal/vfs.Backend`를 구현한다. Windows
마운트 코드는 이 인터페이스만 사용한다. 프로토콜별 제약은 공통 계층에서
숨기지 않고, 지원하지 않는 연산으로 명확하게 반환한다.

이 경계는 다음 목적을 가진다.

- SFTP로 WinFsp 동작을 먼저 검증한 뒤 다른 프로토콜을 추가한다.
- 네트워크 I/O 없이 VFS 및 마운트 동작을 테스트할 수 있게 한다.
- 마운트 라이브러리 선택이 프로토콜 구현 전체에 번지지 않게 한다.

## ADR-002: WinFsp Go 연동 라이브러리

- 상태: 승인
- 날짜: 2026-08-26

Windows 전용 프로젝트이며 Windows 파일 API 의미 보존이 중요하므로
`github.com/winfsp/go-winfsp`의 네이티브 API를 사용한다.
`github.com/winfsp/cgofuse`는 현재 구현 후보에서 제외하고, 확정한 방식으로
해결할 수 없는 호환성 문제가 발견될 때만 다시 검토한다.

0.1 단계에서 메모리 백엔드와 실제 SFTP 백엔드로 다음 항목을 검증했다.

- 빌드 및 WinFsp 런타임 배포 방식
- 파일 생성, 열기, 덮어쓰기, 삭제, 이름 변경
- 한글과 공백이 포함된 파일·폴더 생성
- 파일 읽기·쓰기·삭제·이름 변경·이동
- Windows 탐색기와 메모장의 실제 읽기·저장
- SFTP 경로의 대소문자 구분

Windows 10/11 실제 환경에서 WinFsp 런타임 설치, 드라이브 문자 마운트와
기본 파일 작업을 확인했으며 마운트 실행 중 오류가 발생하지 않았다.

## 데이터 안정성 원칙

쓰기 완료와 서버 반영 성공을 분리하지 않는다. 서버 반영 전 로컬 임시
데이터를 삭제하지 않으며, 장시간 write-back cache는 1.0 필수 범위에서
제외한다. 자격 증명 값은 프로필 구조나 일반 설정 파일에 저장하지 않는다.
