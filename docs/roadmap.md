## 0.4 — FTP/FTPS

- [x] 비밀번호 인증과 원격 시작 경로

- [x] Explicit FTPS 연결

- [x] 파일 생성, 쓰기, 삭제

- [x] 자동 재연결 기본 검증 (제어 연결 단절 후 읽기 복구)
- [x] FTP/FTPS 백엔드를 WinFsp 드라이브로 마운트
- [x] Windows 탐색기 실제 사용 점검

FTP와 두 FTPS 연결 방식의 목록·읽기·쓰기 백엔드, WinFsp 마운트와 모의 서버 자동 테스트를 추가했다. 체크박스 완료 처리는 실제 FTP/FTPS 서버와 Windows 검증 후 진행한다.

2026-08-27 Synology Explicit FTPS CLI와 읽기/쓰기 WinFsp 마운트에서 생성·쓰기·읽기 내용 검증·이동·이름 변경·삭제가 통과했다. 마운트의 쓰기 직후 읽기는 명시적 Flush나 대기 없이 재검증했다. 이후 탐색기·메모장에서 생성·저장·재열기·내용 수정·이름 변경·이동·삭제까지 통과했고, 읽기 전용 기본 검증도 통과했다. 읽기 전용 마운트에서는 제어 연결을 종료한 뒤 같은 프로세스가 새 연결로 기존 파일을 읽는 복구도 확인했다. 같은 날 일반 FTP도 CLI 연결·목록·읽기·쓰기 시나리오와 읽기/쓰기 WinFsp 마운트의 PowerShell 생성·즉시 읽기·이름 변경·이동·삭제를 통과했다. 일반 FTP의 읽기 전용 목록·읽기·ReadOnly 표시·새 파일 생성 차단과 탐색기·메모장 기본 작업도 통과했다. 일반 FTP에서도 파일 작업 완료 후 제어 연결을 종료하고, 동일 PID·변경된 로컬 포트와 오류 없는 읽기 복구를 확인했다. 재연결 기본 검증은 두 모드에서 통과했으나, 전송 중 복구를 의미하지 않는다. Implicit FTPS, 장시간 단절·전송 중 단절·미반영 쓰기 복구와 읽기 전용에서 기존 파일 덮어쓰기·이름 변경·삭제 차단의 실환경 검증도 남아 있다.

0.4의 남은 검증을 미완료로 유지한 채 0.5 첫 구현을 시작했다. Windows 기본
컨트롤 GUI, 트레이, 복수 연결 관리자, 설정 파일과 현재 사용자 DPAPI 암호화를

[데스크톱 검증 체크리스트](desktop-validation.md) 통과 후 갱신한다.
공통 GUI 전체 시나리오는 대표 프로토콜에서 한 번 수행하고, 다른 프로토콜은
연결·읽기 스모크와 백엔드 고유 동작만 검증한다.
