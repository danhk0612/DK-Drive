# 0.5 Windows 데스크톱 첫 검증

상태: 기본 GUI 일부 실환경 검증 완료, 강제 해제 확인 흐름은 실환경 검증 대기.
0.4의 Implicit FTPS와 확장 장애·읽기 전용 미검증 항목은 그대로 남긴다.

## 2026-08-27 확인된 범위

- Explicit FTPS와 HTTPS WebDAV 읽기 전용 GUI 프로필의 연결·기존 파일 읽기·ReadOnly 표시.
- 두 드라이브 동시 연결, 한쪽만 해제한 뒤 다른 쪽 읽기 유지, 전체 연결·해제.
- 트레이 메뉴와 종료, 재실행 시 프로필·옵션 복원 및 미저장 비밀번호 공란.
- WebDAV의 선택적 DPAPI 비밀번호 저장 후 재실행·무입력 연결, 프로그램 시작 시 자동 연결.
- Windows 로그인 자동 실행 등록값의 실행 파일 인용·`--tray` 확인, 해제 시 DKDrive 값 제거.
- 기존 안전 해제: 읽기 핸들을 열어 둔 동안 드라이브 유지, 핸들을 닫고 해제하면 드라이브 제거.

실제 Windows 재로그인, GUI SFTP/쓰기 작업, 프로필 삭제, 업로드 실패 상태의 실환경
해제는 이 결과에 포함하지 않는다. 새 강제 해제 기능은
[일괄 재검증 절차](desktop-force-disconnect-validation.md)로 별도 확인한다.

## 빌드·첫 실행

기존 CLI 마운트와 이전 GUI를 정상 종료하고 빌드한다. 드라이브 문자는 현재
Windows에서 사용하지 않는 문자를 선택한다. WinFsp 설치는 기존 CLI와 동일하다.

```powershell
git pull
go test ./...
go vet ./...
go build -ldflags="-H=windowsgui" -o bin/dkdrive.exe ./cmd/dkdrive
.\bin\dkdrive.exe
```

- 창·입력칸·연결 목록·버튼·트레이 아이콘 표시
- 창 제목은 `0.5.0-dev`; 최초 연결 목록은 비어 있음
- 비밀번호/Passphrase 저장과 자동 시작·자동 연결은 기본 해제
- 같은 사용자 세션에서 재실행하면 기존 창 복원, 두 번째 GUI는 시작하지 않음
- 초기 화면은 Windows 기본 아이콘을 사용; 제품 아이콘과 고급·캐시 탭은 미구현

## 연결 프로필

실서버 검증이 끝난 프로토콜부터 하나씩 입력한다. 사용자 운영 주소·계정·비밀번호를
이 문서나 저장소에 기록하지 않는다.

1. 새 연결 → 이름·드라이브·프로토콜·호스트·포트·원격 경로·사용자 입력.
2. 비밀번호 인증은 비밀번호 입력. SFTP 개인키는 전체 파일 경로를 입력하고,
   암호화 키이면 Passphrase도 입력. 개인키 칸이 비어 있으면 비밀번호 인증이다.
3. SFTP known_hosts 공란은 현재 사용자의 `.ssh/known_hosts` 사용. 없는 키나
   변경된 키는 연결 실패로 표시하며 GUI가 자동 신뢰하지 않는다.
4. 연결 테스트 → 인증과 원격 시작 경로만 확인. 원격 파일 변경이나 마운트 없음.
5. 저장 → 선택 연결. 저장하지 않은 입력 변경은 실제 마운트에 적용되지 않는다.
6. 인증서 검증은 기본 활성화. 검증 우회는 명시적 체크·경고 확인이 필요하고,
   일반 FTP/HTTP의 평문 전송도 저장/연결 테스트 시 경고한다.

비밀번호 저장을 선택하지 않으면 저장 버튼으로 현재 프로세스 메모리에만
비밀값을 보관한다. 재실행 후 비밀번호를 입력하고 저장을 다시 눌러야 한다.
저장을 선택하면 현재 Windows 사용자 DPAPI로 암호화하며, 다른 사용자/PC로
복사해서 복호화하는 용도가 아니다. 저장 체크 해제 후 저장하면 해당 프로필의
암호화 비밀값을 설정에서 제거한다. 백업·동기화 사본까지 지우는 기능은 아니다.

설정 파일: `%APPDATA%\DKDrive\settings.json`.
비밀번호·Passphrase 원문은 JSON에 없어야 한다. 암호화 값도 외부에 공유하지 않는다.
설정이 손상되었거나 지원하지 않는 버전이면 시작 오류를 표시하고 원본은 유지한다.

## 복수 연결과 기본 작업

- 다른 드라이브 문자에 두 개 이상의 프로필 등록, 각각 연결·해제
- 중복 문자 저장과 이미 사용 중인 Windows 드라이브 연결 거부
- 하나의 잘못된 연결이 기존 정상 마운트에 영향을 주지 않는지 확인
- 마운트된 각 드라이브에서 목록·기존 파일 읽기 확인
- 별도 새 테스트 폴더에서 생성·저장·즉시 읽기·이름 변경·이동·삭제 확인
- 읽기 전용 프로필은 읽기 유지·ReadOnly 표시·새 파일 생성 차단 확인
- 연결된 프로필은 해제 전까지 수정·삭제 거부

목록의 연결 상태는 WinFsp 마운트 상태이며, 원격 소켓의 실시간 건강 상태를
감시하는 표시는 아니다. 네트워크 복구는 기존 백엔드의 동작을 사용한다.

원격 파일 테스트는 기존 파일을 변경하지 않고 새 테스트 폴더에서만 진행한다.
테스트가 실패하면 그 시점의 파일과 캐시를 보존한다.

## 트레이·설정·자동 시작

- 창 닫으면 트레이로: 체크 시 X 버튼은 창을 숨기고 마운트는 유지
- 트레이 더블클릭 또는 창 열기: 기존 창 복원
- 트레이의 드라이브별 항목은 연결/해제, 전체 연결·해제와 종료도 확인
- 창 닫으면 트레이로 체크 해제 시 X 버튼은 안전한 종료 절차 수행
- 설정 저장 후 프로그램 종료·재실행: 프로필과 옵션 복원
- 비밀번호 저장 선택 후 재실행: 다시 입력하지 않고 수동 연결
- 연결별 자동 연결: 저장한 자격 증명으로 프로그램 시작 시 연결
- Windows 로그인 시 실행: 체크 시 HKCU Run의 DKDrive 값만 등록, 해제 시 제거
- 자동 실행과 자동 연결을 각각 독립적으로 켜고 끄는지 확인

자동 실행 등록은 현재 실행 파일의 전체 경로와 `--tray`를 사용한다. 실행 파일을
다른 위치로 이동하면 등록을 해제·재등록한다. 다른 프로그램의 Run 값은 변경하지 않는다.
암호화 키의 자동 연결에도 저장한 Passphrase가 필요하다. 네트워크 미준비 시 첫
연결 실패를 표시하며, 초기 자동 연결을 무한 반복하는 기능은 이 단계에 포함하지 않는다.

## 안전한 해제·종료

일반 해제는 열린 파일/폴더 핸들이나 기록된 파일 닫기·업로드 실패가 있으면
거부한다. 이후 실패한 연결마다 강제 해제 여부를 묻는다. 기본 선택은 아니요이며,
취소하면 연결을 유지한다. 선택 해제, 트레이의 개별 해제, 전체 해제와 프로그램
종료에 같은 흐름을 사용한다. 전체 해제 중 이미 해제된 연결을 다시 연결하지 않는다.
연결·해제와 확인창 처리 중에는 다른 관리 작업을 시작하지 않는다.

- 별도 테스트 파일을 열어 둔 상태에서 해제 거부 확인
- 파일 닫기·저장 후 다시 해제 성공, 다른 연결은 유지되는지 확인
- 프로그램 종료 시 모든 드라이브가 해제되고 프로세스·트레이가 사라지는지 확인
- 파일 닫기/업로드 실패 시 캐시 위치 안내와 강제 해제 확인창 표시
- 강제 해제 취소 시 연결 유지, 승인 시 해당 드라이브 제거 및 캐시 안내
- 종료 중 하나라도 취소/실패하면 프로그램 유지, 모두 해제되면 프로그램 종료

마지막 실패 항목은 모의 서버 자동 테스트로 먼저 확인한다. 실제 NAS 장애를
임의로 만들지 않는다. 실패 캐시의 자동 복구 UI는 아직 없으므로 오류가 나면
캐시를 삭제하지 말고 결과를 보고한다. 승인한 강제 해제는 남아 있는 임시 파일을
로컬 동기화·닫기하고 보존하며 추가 업로드나 자동 복구를 하지 않는다. 로컬 동기화/닫기
오류는 강제 해제 후 경고로 표시한다. 응용 프로그램/Windows 버퍼에서 DKDrive로
전달되지 않은 데이터나 이미 전송 중이던 원격 변경의 온전함은 보장하지 않는다.
진행 중인 파일 작업의 반환을 기다릴 수 있어 강제 해제가 즉시 끝난다는 보장은 없다.
Windows 로그오프/종료 전에 DKDrive를 먼저 정상 종료한다. 살아 있는 연결이
있으면 일반 OS 종료 요청을 거부하지만, 강제 종료나 전원 차단은 막을 수 없다.

## 자동 테스트와 수동 검증의 경계

자동 테스트: 프로필 검증, 설정 교체·손상 거부, 비밀값 분리, DPAPI 왕복·변조 거부,
복수 연결·중복 예약·실패 복구 상태, 열린 핸들 해제 거부, 업로드 실패 캐시 보존,
확인 승인/취소·일부 연결 실패, 강제 해제 시 미업로드 임시 파일 보존·업로드 미재시도,
Win32 구조체 크기·자동 시작 명령 인용과 Windows 빌드.

화면 배치·DPI·키보드 탐색·Shell 트레이 조작·로그인 후 실행·실제 WinFsp 복수
마운트는 사용자 PC에서 확인해야 한다. 자동 테스트 통과만으로 완료 처리하지 않는다.
