# 0.5 Windows 데스크톱 첫 검증

상태: 기본 GUI와 강제 해제 확인 흐름 일부 실환경 검증 완료.
0.4의 Implicit FTPS와 확장 장애·읽기 전용 미검증 항목은 그대로 남긴다.

## 2026-08-27 확인된 범위

- Explicit FTPS와 HTTPS WebDAV 읽기 전용 GUI 프로필의 연결·기존 파일 읽기·ReadOnly 표시.
- 두 드라이브 동시 연결, 한쪽만 해제한 뒤 다른 쪽 읽기 유지, 전체 연결·해제.
- 트레이 메뉴와 종료, 재실행 시 프로필·옵션 복원 및 미저장 비밀번호 공란.
- WebDAV의 선택적 DPAPI 비밀번호 저장 후 재실행·무입력 연결, 프로그램 시작 시 자동 연결.
- Windows 로그인 자동 실행 등록값의 실행 파일 인용·`--tray` 확인, 해제 시 DKDrive 값 제거.
- 기존 안전 해제: 읽기 핸들을 열어 둔 동안 드라이브 유지, 핸들을 닫고 해제하면 드라이브 제거.
- 강제 해제 승인 시 드라이브 제거·기존 읽기 핸들 취소·캐시 위치 안내, 재연결 후 원격 내용 유지.
- 강제 해제 기본값 아니요 선택 시 별도 오류창 없이 드라이브·기존 읽기 핸들 유지.
- 전체 해제에서 FTPS 취소·WebDAV 승인 시 FTPS만 유지, 프로그램 종료 취소 시
  프로세스·WebDAV·기존 핸들 유지, 다시 승인하면 드라이브·프로세스 제거.
- 원격 연결 없이 임시 WebDAV 프로필 생성·저장, 연결 이름·읽기 전용 편집과
  재선택 복원, 프로필 삭제 후 설정 JSON에서 제거.
- WebDAV GUI 읽기/쓰기 프로필에서 격리 폴더 생성·쓰기·즉시 읽기·한글 이름 변경·
  폴더 간 이동·내용 검증·삭제, 읽기 전용 프로필에서 새 폴더 생성 차단.
- 미저장 입력의 `저장 *` 표시와 다른 프로필 전환 시 저장·버리기·취소, 저장 후
  목록 선택과 편집 대상 일치.
- DK-Drive `D` 제품 아이콘의 창 제목·트레이 표시, 트레이 메뉴·창 복원·종료.
- 드라이브 문자 드롭다운, SFTP 개인키 파일 선택과 프로필 재선택 후 경로 복원.
- 프로필 목록의 드라이브·연결 이름·프로토콜·상태 열, 긴 이름 열 조절, 선택 행과
  우측 편집 내용 동기화 및 연결 상태별 버튼 활성화.
- 2026-09-01 프로토콜별 입력 활성화, 비밀값 보기 전환, Tab 순서, Ctrl+S, Esc,
  최대화·창 크기 조절·최소 크기, 확대 배치와 텍스트 입력의 Ctrl+A 전체 선택.

실제 Windows 재로그인, GUI SFTP/쓰기 작업, 업로드 실패 상태의 실환경
해제는 이 결과에 포함하지 않는다. 강제 해제의 상세 결과와 남은 경계는
[일괄 재검증 절차](desktop-force-disconnect-validation.md)에 기록한다.

## 빌드·첫 실행

기존 CLI 마운트와 이전 GUI를 정상 종료하고 빌드한다. 드라이브 문자는 현재
Windows에서 사용하지 않는 문자를 선택한다. WinFsp 설치는 기존 CLI와 동일하다.

```powershell
git pull
go test ./...
go vet ./...
go build -ldflags="-H=windowsgui" -o bin/dkdrive.exe ./cmd/dkdrive
.\bin\dkdrive.exe
```

- 창·입력칸·연결 목록·버튼·트레이 아이콘 표시
- 창 제목은 `0.5.0-dev`; 최초 연결 목록은 비어 있음
- 비밀번호/Passphrase 저장과 자동 시작·자동 연결은 기본 해제
- 같은 사용자 세션에서 재실행하면 기존 창 복원, 두 번째 GUI는 시작하지 않음
- 창 제목과 트레이에 파란색 DK-Drive `D` 아이콘 표시
- 고급·캐시 탭은 미구현

## 연결 프로필

실서버 검증이 끝난 프로토콜부터 하나씩 입력한다. 사용자 운영 주소·계정·비밀번호를
이 문서나 저장소에 기록하지 않는다.

1. 새 연결 → 이름·드라이브·프로토콜·호스트·포트·원격 경로·사용자 입력.
2. 비밀번호 인증은 비밀번호 입력. SFTP 개인키는 전체 파일 경로를 입력하고,
   암호화 키이면 Passphrase도 입력. 개인키 칸이 비어 있으면 비밀번호 인증이다.
3. SFTP known_hosts 공란은 현재 사용자의 `.ssh/known_hosts` 사용. 없는 키나
   변경된 키는 연결 실패로 표시하며 GUI가 자동 신뢰하지 않는다.
4. 연결 테스트 → 인증과 원격 시작 경로만 확인. 원격 파일 변경이나 마운트 없음.
5. 입력을 변경하면 저장 버튼이 `저장 *`로 표시된다. 다른 프로필이나 새 연결로
   이동할 때 저장·버리기·취소를 선택하며, 취소가 기본값이다. 저장 검증 또는 기록이
   실패하면 현재 편집 화면을 유지한다. 저장 → 선택 연결 순서로 마운트한다.
6. 인증서 검증은 기본 활성화. 검증 우회는 명시적 체크·경고 확인이 필요하고,
   일반 FTP/HTTP의 평문 전송도 저장/연결 테스트 시 경고한다.

연결 이름은 프로필 목록·트레이 표시와 Windows 볼륨명에 공통으로 사용한다.
기존 설정의 `VolumeName` 값은 읽기 호환을 위해 유지하지만 새로 저장하면 연결
이름으로 동기화한다.

비밀번호 저장을 선택하지 않으면 저장 버튼으로 현재 프로세스 메모리에만
비밀값을 보관한다. 재실행 후 비밀번호를 입력하고 저장을 다시 눌러야 한다.
저장을 선택하면 현재 Windows 사용자 DPAPI로 암호화하며, 다른 사용자/PC로
복사해서 복호화하는 용도가 아니다. 저장 체크 해제 후 저장하면 해당 프로필의
암호화 비밀값을 설정에서 제거한다. 백업·동기화 사본까지 지우는 기능은 아니다.

설정 파일: `%APPDATA%\DKDrive\settings.json`.
비밀번호·Passphrase 원문은 JSON에 없어야 한다. 암호화 값도 외부에 공유하지 않는다.
설정이 손상되었거나 지원하지 않는 버전이면 시작 오류를 표시하고 원본은 유지한다.

## 프로필 목록 표시

- 목록 머리글에 `드라이브`, `연결 이름`, `프로토콜`, `상태` 네 열이 표시되는지 확인
- 긴 한글 연결 이름이 있으면 `연결 이름` 열 경계를 끌어 전체 내용을 확인
- SFTP, WebDAV HTTP/HTTPS, FTP, Explicit/Implicit FTPS가 별도 프로토콜명으로 표시
- 프로필을 바꿔 선택해도 강조된 행과 우측 편집 내용이 같은 프로필인지 확인
- 미저장 변경이 있는 상태에서 다른 행을 선택하고 저장·버리기·취소를 각각 확인
- 연결 안 된 행은 `연결·삭제`, 연결된 행은 `해제` 버튼만 활성화되는지 확인
- 저장·연결·해제 후에도 현재 행 선택이 유지되고 상태 열이 갱신되는지 확인

상태 열은 현재 WinFsp 마운트 작업 상태를 표시하며 원격 서버를 지속적으로 감시하지
않는다. 마지막 연결 오류와 발생 시각은 후속 연결 진단 단계에서 추가한다.

## 비밀값 표시 전환

- 비밀번호와 키 Passphrase는 프로필을 처음 열 때 마스킹되어 있는지 확인
- `보기`를 누르면 해당 입력만 원문으로 표시되고 버튼이 `숨기기`로 바뀌는지 확인
- `숨기기`를 누르면 즉시 다시 마스킹되는지 확인
- SFTP 개인키 사용 시 비밀번호 보기 버튼은 비활성화되고 Passphrase 보기 버튼만
  활성화되는지 확인
- 비밀번호 인증이나 WebDAV/FTP/FTPS에서는 비밀번호 보기 버튼만 활성화되는지 확인
- 비밀값을 표시한 상태에서 다른 프로필 또는 새 연결로 이동한 뒤 돌아오면 다시
  마스킹되어 있는지 확인

보기 상태는 화면 표시만 바꾸며 저장 여부나 DPAPI 암호화 정책은 변경하지 않는다.

## 창 배치·DPI·키보드

- 창을 가로·세로로 늘렸을 때 프로필 목록과 상태 영역이 늘어나고 입력 필드가
  오른쪽 여백까지 확장되는지 확인
- 창을 최소 크기보다 작게 줄일 수 없고 최소 크기에서 글자·버튼·입력칸이
  겹치거나 잘리지 않는지 확인
- Windows 디스플레이 배율 100%, 125%, 150%, 200%에서 프로그램을 다시 실행해
  주요 입력과 버튼이 화면 안에 표시되는지 확인
- SFTP 비밀번호·개인키 인증과 다른 프로토콜을 바꿀 때 비활성 입력과 하단 인증
  설명이 일치하는지 확인
- `Tab`과 `Shift+Tab`만으로 목록, 프로필 입력, 저장, 연결 테스트 버튼까지
  순서대로 이동할 수 있는지 확인
- 입력을 변경한 뒤 `Ctrl+S`로 저장되는지 확인
- 각 텍스트 입력칸에서 `Ctrl+A`로 현재 값 전체가 선택되는지 확인
- 입력을 변경한 뒤 `Esc`를 누르면 변경 폐기 확인창이 나타나고 기본 선택이
  아니요인지 확인
- 변경 폐기를 승인하면 현재 저장 프로필 값 또는 빈 새 연결 화면으로 복원되고,
  취소하면 편집 내용과 `저장 *` 상태가 유지되는지 확인

리사이즈와 배율 변경은 연결·캐시 동작을 바꾸지 않는다. 배율별 확인은 실행 중인
마운트를 모두 정상 해제하고 DK-Drive를 다시 실행한 뒤 수행한다.

## 복수 연결과 기본 작업

- 다른 드라이브 문자에 두 개 이상의 프로필 등록, 각각 연결·해제
- 중복 문자 저장과 이미 사용 중인 Windows 드라이브 연결 거부
- 하나의 잘못된 연결이 기존 정상 마운트에 영향을 주지 않는지 확인
- 마운트된 각 드라이브에서 목록·기존 파일 읽기 확인
- 별도 새 테스트 폴더에서 생성·저장·즉시 읽기·이름 변경·이동·삭제 확인
- 읽기 전용 프로필은 읽기 유지·ReadOnly 표시·새 파일 생성 차단 확인
- 연결된 프로필은 해제 전까지 수정·삭제 거부

목록의 연결 상태는 WinFsp 마운트 상태이며, 원격 소켓의 실시간 건강 상태를
감시하는 표시는 아니다. 네트워크 복구는 기존 백엔드의 동작을 사용한다.

원격 파일 테스트는 기존 파일을 변경하지 않고 새 테스트 폴더에서만 진행한다.
테스트가 실패하면 그 시점의 파일과 캐시를 보존한다.

## 트레이·설정·자동 시작

- 창 닫으면 트레이로: 체크 시 X 버튼은 창을 숨기고 마운트는 유지
- 트레이 더블클릭 또는 `DK-Drive 실행`: 기존 창 복원
- 트레이의 `드라이브` 하위 메뉴에서 프로필별 항목을 클릭해 연결/해제 토글,
  드라이브 추가와 전체 연결·해제를 확인
- 트레이의 `캐시 관리 > 캐시 폴더 열기`로 캐시 위치가 열리고,
  `캐시 관리 > 캐시 정리`는 연결 중 차단되는지 확인
- 모든 드라이브를 해제한 뒤 `캐시 정리`에서 기본값 아니요로 취소하고,
  다시 실행해 승인하면 모든 캐시 항목이 제거되고 캐시 폴더는 남는지 확인
- 창 닫으면 트레이로 체크 해제 시 X 버튼은 안전한 종료 절차 수행
- 설정 저장 후 프로그램 종료·재실행: 프로필과 옵션 복원
- 미저장 입력 변경 시 `저장 *` 표시, 다른 프로필·새 연결 선택 시 저장·버리기·취소
  동작과 취소 시 현재 선택·입력 유지
- 비밀번호 저장 선택 후 재실행: 다시 입력하지 않고 수동 연결
- 연결별 자동 연결: 저장한 자격 증명으로 프로그램 시작 시 연결
- Windows 로그인 시 실행: 체크 시 HKCU Run의 DKDrive 값만 등록, 해제 시 제거
- 자동 실행과 자동 연결을 각각 독립적으로 켜고 끄는지 확인

자동 실행 등록은 현재 실행 파일의 전체 경로와 `--tray`를 사용한다. 실행 파일을
다른 위치로 이동하면 등록을 해제·재등록한다. 다른 프로그램의 Run 값은 변경하지 않는다.
암호화 키의 자동 연결에도 저장한 Passphrase가 필요하다. 네트워크 미준비 시 첫
연결 실패를 표시하며, 초기 자동 연결을 무한 반복하는 기능은 이 단계에 포함하지 않는다.

## 안전한 해제·종료

일반 해제는 Windows 셸이 유지하는 디렉터리 열거 핸들은 안전하게 닫는다. 열린
파일 핸들이나 기록된 파일 닫기·업로드 실패가 있으면 거부한다. 이후 실패한 연결마다
강제 해제 여부를 묻는다. 기본 선택은 아니요이며,
취소하면 연결을 유지한다. 선택 해제, 트레이의 개별 해제, 전체 해제와 프로그램
종료에 같은 흐름을 사용한다. 전체 해제 중 이미 해제된 연결을 다시 연결하지 않는다.
연결·해제와 확인창 처리 중에는 다른 관리 작업을 시작하지 않는다.

- 별도 테스트 파일을 열어 둔 상태에서 해제 거부 확인
- 파일 닫기·저장 후 다시 해제 성공, 다른 연결은 유지되는지 확인
- 프로그램 종료 시 모든 드라이브가 해제되고 프로세스·트레이가 사라지는지 확인
- 파일 닫기/업로드 실패 시 캐시 위치 안내와 강제 해제 확인창 표시
- 강제 해제 취소 시 연결 유지, 승인 시 해당 드라이브 제거 및 캐시 안내
- 종료 중 하나라도 취소/실패하면 프로그램 유지, 모두 해제되면 프로그램 종료
- 자동 연결 직후 파일을 열지 않고 일반 해제하면 강제 해제 확인 없이 성공하는지 확인
- 읽기 파일을 열어 둔 상태에서는 계속 거부되고, 닫은 뒤 일반 해제되는지 확인
- 두 과정에서 새 보존 캐시 항목이 생기지 않는지 확인

마지막 실패 항목은 모의 서버 자동 테스트로 먼저 확인한다. 실제 NAS 장애를
임의로 만들지 않는다. 복구 UI는 자동 업로드하지 않으므로 오류가 나면 캐시를
삭제하지 말고 결과를 보고한다. 승인한 강제 해제는 남아 있는 임시 파일을
로컬 동기화·닫기하고 보존하며 추가 업로드나 자동 복구를 하지 않는다. 로컬 동기화/닫기
오류는 강제 해제 후 경고로 표시한다. 응용 프로그램/Windows 버퍼에서 DK-Drive로
전달되지 않은 데이터나 이미 전송 중이던 원격 변경의 온전함은 보장하지 않는다.
진행 중인 파일 작업의 반환을 기다릴 수 있어 강제 해제가 즉시 끝난다는 보장은 없다.
Windows 로그오프/종료 전에 DK-Drive를 먼저 정상 종료한다. 살아 있는 연결이
있으면 일반 OS 종료 요청을 거부하지만, 강제 종료나 전원 차단은 막을 수 없다.

## 연결 관리 UI 개편 후 Windows 확인

자동 테스트와 Windows GUI 빌드가 통과한 뒤 다음 순서로 한 번만 확인한다. 기존
프로토콜별 파일 작업과 대용량 복구 전송은 반복하지 않는다.

1. 프로그램을 실행하고 연결 관리 창이 연결 목록·기본 프로그램 기능·선택/전체
   작업만 표시하는 축소 레이아웃인지 확인한다.
2. 연결되지 않은 프로필은 트레이 드라이브 메뉴에서 `[X]`, 연결된 프로필은 `[O]`로
   표시되는지 확인한다. 메뉴 문구가 `전체 연결`, `전체 해제`, `폴더 열기`인지 확인한다.
3. 트레이 아이콘에 마우스를 올려 연결이 없으면 `DK-Drive`, 연결이 있으면 드라이브
   문자가 정렬된 `DK-Drive [C D E]` 형식인지 확인한다. 연결·해제 직후에도 갱신되는지
   확인한다.
4. 목록 선택 뒤 `설정`과 더블클릭이 같은 별도 설정 창을 여는지 확인한다. `새 연결`도
   빈 설정 창을 열고, 저장·연결 테스트·비밀값 보기/숨기기·파일 찾아보기가 동작하는지
   확인한다.
5. 설정 변경 뒤 제목 표시줄 X 또는 `닫기`를 눌러 저장·버리기·취소 선택이 각각
   동작하는지 확인한다. 연결 중인 프로필은 열람 가능하지만 저장 변경은 거부되는지
   확인한다.
6. 보존 캐시 창을 연 상태에서 연결 관리 창의 목록 선택과 연결·해제 작업이 가능한지
   확인한다. 보존 캐시 버튼을 다시 누르면 새 창을 만들지 않고 기존 창을 앞으로
   가져오는지 확인한다.
7. 원격 재시도 중에는 복구 창 닫기와 프로그램 종료가 계속 차단되고, 연결 관리 창은
   표시·조작 가능한지 확인한다. 재시도 완료 뒤 두 창을 정상적으로 닫을 수 있어야 한다.
8. 100%, 150% DPI에서 두 창의 컨트롤이 잘리거나 겹치지 않는지 확인하고 Tab 이동,
   `Ctrl+S`, 입력칸 `Ctrl+A`, 변경 취소 `Esc`를 한 번씩 확인한다.

쓰기 검증은 `DK-Drive 검증/<프로토콜>/<실행 시각>/` 형태의 새 격리 경로에서 수행하고
성공 시에만 삭제한다. 기존 운영 파일이나 다른 프로토콜의 테스트 경로를 재사용하지
않는다. 현재 WebDAV GUI 전체 시나리오와 SFTP·FTP·Explicit FTPS WinFsp 전체
시나리오가 통과했으므로 SFTP GUI 전체 쓰기 시나리오는 반복하지 않는다.

## 자동 테스트와 수동 검증의 경계

자동 테스트: 프로필 검증, 설정 교체·손상 거부, 비밀값 분리, DPAPI 왕복·변조 거부,
복수 연결·중복 예약·실패 복구 상태, 열린 핸들 해제 거부, 업로드 실패 캐시 보존,
확인 승인/취소·일부 연결 실패, 강제 해제 시 미업로드 임시 파일 보존·업로드 미재시도,
보존 메타데이터 정합성·경로 이탈 차단·로컬 내보내기 바이트 일치·선택 삭제 범위,
Win32 구조체 크기·자동 시작 명령 인용과 Windows 빌드.

화면 배치·DPI·키보드 탐색·Shell 트레이 조작·로그인 후 실행·실제 WinFsp 복수
마운트는 사용자 PC에서 확인해야 한다. 자동 테스트 통과만으로 완료 처리하지 않는다.
