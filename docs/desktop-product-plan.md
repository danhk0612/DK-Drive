# DK-Drive 데스크톱 제품화 계획

## 목적과 현재 위치

DK-Drive `0.5.0-dev`는 SFTP, WebDAV, FTP와 Explicit FTPS의 기본 파일 작업,
WinFsp 마운트, 복수 프로필 GUI와 트레이 동작을 실제 Windows 환경에서 검증했다.
이 문서는 현재 기술 검증형 화면을 일반 사용자가 반복 사용하고 실패를 복구할 수
있는 데스크톱 프로그램으로 정리하기 위한 구현 순서와 완료 기준을 고정한다.

이 문서의 원칙은 다음과 같다.

- 공통 GUI 전체 시나리오는 대표 프로토콜에서 한 번 검증하고, 나머지 프로토콜은
  연결·인증·목록·읽기와 백엔드 고유 동작만 검증한다.
- 모의 서버 자동 테스트와 실제 Windows/NAS 검증 결과를 구분한다.
- 실패한 스테이징 파일은 복구 정보와 사용자 확인 없이 자동 삭제하거나 자동으로
  원격 서버에 다시 올리지 않는다.
- 자격 증명과 Passphrase는 캐시 복구 메타데이터에 기록하지 않는다.
- 각 단계는 아래 완료 기준을 충족한 뒤 다음 단계로 진행한다.

## 실행 순서

1. 드라이브 문자 선택 드롭다운
2. SFTP 개인키·known_hosts Windows 파일 선택
3. 프로필 목록과 연결 상태 표시 개편
4. 프로토콜별 입력 표시, 창 크기·DPI·키보드 조작 정리
5. 보존 캐시 메타데이터와 시작 시 정합성 검사
6. 캐시 목록·폴더 열기·로컬 내보내기 UI
7. 복구 항목 명시적 삭제
8. 원격 재시도와 충돌 처리
9. 캐시 용량·보존 정책
10. 연결 진단 정보
11. 배포 패키징과 릴리스 검증

## 0.6A — 프로필 편집 UI

### 1. 드라이브 문자 드롭다운

변경 범위:

- 자유 입력 필드를 `A:`부터 `Z:`까지 선택하는 드롭다운으로 변경한다.
- 현재 Windows에서 사용 중인 드라이브와 다른 저장 프로필이 예약한 문자를
  선택 불가로 표시한다. 현재 편집 중인 프로필의 문자는 계속 선택할 수 있다.
- 저장과 연결 직전에 실제 사용 여부를 다시 검사하여 화면을 연 뒤 상태가 바뀐
  경우도 차단한다.

완료 기준:

- 잘못된 길이·문자를 입력할 수 없다.
- 중복 프로필 문자와 이미 사용 중인 Windows 드라이브 문자를 저장하거나 연결할
  수 없고 원인이 사용자에게 표시된다.
- 프로필 전환·재실행 후 기존 선택이 정확히 복원된다.

### 2. Windows 파일 선택

변경 범위:

- SFTP 개인키와 `known_hosts` 옆에 찾아보기 버튼을 둔다.
- Windows 공용 파일 선택 창으로 파일 하나를 선택하고 절대 경로만 저장한다.
- 직접 입력과 붙여넣기는 계속 지원한다.
- 선택 취소는 기존 값을 유지하고, 파일 선택은 미저장 변경 상태로 처리한다.
- 개인키 선택은 흔히 쓰는 키 파일을 우선 보여주되 모든 파일을 선택할 수 있게
  한다. `known_hosts`도 파일 선택만 허용한다.

완료 기준:

- 한글·공백이 포함된 경로가 저장·복원·연결 테스트에 그대로 전달된다.
- 파일 내용을 설정이나 로그에 복사하지 않는다.
- 존재하지 않는 경로의 기존 검증과 오류 안내가 유지된다.

### 3. 프로필 목록 개편

변경 범위:

- 한 줄 문자열 목록을 `드라이브`, `연결 이름`, `프로토콜`, `상태`가 구분되는
  Windows 목록 보기로 변경한다.
- 긴 연결 이름은 열 너비 조절 또는 툴팁으로 전체 내용을 확인할 수 있게 한다.
- 목록 갱신 뒤 현재 선택을 유지하고, 연결 상태 문구를 중복 표기하지 않는다.
- 선택·연결 상태에 따라 저장, 삭제, 연결, 해제 버튼을 활성화한다.

완료 기준:

- 긴 한글 프로필 이름과 모든 지원 프로토콜 이름이 어색하게 잘리지 않는다.
- 저장·연결·해제 뒤 선택 행과 실제 우측 편집 내용이 일치한다.
- 연결됨·연결 중·연결 안 됨·오류 상태를 서로 구분할 수 있다.

### 4. 화면 배치와 입력 동작

변경 범위:

- 선택한 프로토콜에 사용하지 않는 필드는 숨기거나 비활성화하고 이유를 명확히
  표시한다.
- 고정 좌표 화면을 최소 창 크기와 리사이즈에 대응하도록 정리한다.
- Windows 배율 100%, 125%, 150%, 200%에서 글자·버튼이 잘리지 않게 한다.
- Tab 순서, 기본 버튼, Esc 취소와 키보드 포커스를 정리한다.
- 비밀번호와 Passphrase는 기본 마스킹을 유지하고, 값의 노출 상태가 명확한
  보기 전환 버튼을 제공한다.
- 저장되지 않은 변경의 강조와 저장·버리기·취소 확인은 현재 동작을 유지한다.

완료 기준:

- 지원 배율과 최소 창 크기에서 겹침·잘림 없이 주요 작업을 완료할 수 있다.
- 마우스 없이 프로필 선택, 편집, 저장과 연결 테스트까지 이동할 수 있다.
- 프로필을 전환한 뒤 목록 선택과 우측 편집 내용이 항상 같은 프로필을 가리킨다.

## 0.6B — 안전한 캐시 복구

현재 캐시는 `staging-*` 임시 파일만 남기므로 원래 프로필과 원격 경로를 자동으로
판별할 수 없다. 복구 화면보다 메타데이터 형식을 먼저 구현한다.

### 5. 보존 캐시 메타데이터

각 보존 항목에 다음 정보를 버전이 있는 메타데이터로 원자적으로 기록한다.

- 프로필 ID와 표시 이름, 프로토콜
- 원격 경로와 로컬 스테이징 경로
- 파일 크기, 생성·갱신·보존 시각
- 보존 사유와 마지막 오류, 복구 상태

메타데이터에는 비밀번호, 키 Passphrase, 개인키 내용과 인증 헤더를 넣지 않는다.
프로그램 시작 시 메타데이터만 남거나 파일만 남은 경우를 정합성 검사하며,
기존 `staging-*`는 삭제하지 않고 `메타데이터 없음` 항목으로 표시한다.

완료 기준:

- 업로드 실패와 강제 해제 자동 테스트에서 원격 경로와 보존 사유를 확인할 수 있다.
- 중간 종료 중에도 기존 메타데이터가 부분 JSON으로 손상되지 않는다.
- 캐시 루트 밖의 경로를 가리키는 조작된 메타데이터는 복구 대상으로 사용하지 않는다.

### 6. 캐시 목록과 로컬 내보내기

첫 복구 UI는 원격 서버를 변경하지 않는 기능만 제공한다.

- 보존 항목 목록과 상세 오류를 표시한다.
- 캐시 폴더 열기와 목록 새로 고침을 제공한다.
- 사용자가 Windows 저장 위치를 선택하여 원본을 로컬 파일로 내보낼 수 있게 한다.
- 내보내기 성공 여부와 대상 경로를 명확히 표시한다.

완료 기준:

- 연결 프로필을 삭제했거나 서버가 오프라인이어도 로컬 내보내기가 가능하다.
- 한글·공백 이름과 큰 파일을 원본 바이트 그대로 내보낸다.
- 내보내기 실패 시 원본 캐시와 메타데이터를 그대로 보존한다.

### 7. 명시적 삭제

- 항목별 삭제만 먼저 제공하고 파일명·원격 경로·크기를 확인창에 표시한다.
- 삭제 실패는 항목을 목록에 유지한다.
- 메타데이터 없는 파일에는 현재 연결이 사용하는 스테이징 파일이 포함될 수 있으므로
  연결된 드라이브가 있으면 삭제를 차단한다.
- 캐시 루트 바로 아래의 스테이징 파일과 연결된 메타데이터만 삭제하며 디렉터리와
  캐시 밖 경로는 거부한다.
- 트레이의 전체 캐시 정리는 사용자 요청에 따라 먼저 제공한다. 연결된 드라이브가
  없을 때만 실행하며, 되돌릴 수 없다는 확인 후 캐시 폴더의 모든 항목을 삭제한다.
- 자동 정리는 캐시 정책 단계 전에는 제공하지 않는다.

### 8. 원격 재시도와 충돌

로컬 내보내기와 명시적 삭제가 검증된 뒤 원격 재시도를 추가한다.

- 사용자가 복구 프로필을 선택하고 필요하면 다시 인증한 뒤에만 전송한다.
- 원격 파일 존재 또는 변경이 감지되면 덮어쓰기, 다른 이름, 건너뛰기 중 사용자가
  선택하게 한다.
- 전송 성공과 원격 결과 확인 뒤에만 캐시 삭제를 제안한다.
- 프로그램 시작 시 자동 재시도하지 않는다.

충돌 비교는 원격 크기와 수정 시각을 사용한다. 크기가 같고 양쪽 수정 시각 차이가
2초 이하일 때만 동일 파일로 판정하며, 서버가 수정 시각을 제공하지 않거나 그 밖의
경우는 충돌로 취급한다. 이 기준은 ETag를 제공하지 않는 SFTP·FTP와 현재 공통 VFS
계약에서도 동일하게 적용한다.

2026-09-02 WebDAV Windows 실환경에서 원격 파일 없음 전송과 결과 크기 확인,
건너뛰기·다른 이름·덮어쓰기, 성공 뒤 캐시 유지와 512 MiB 전송 중 복구 창 닫기
차단을 확인했다. 원격 상위 폴더까지 없으면 WebDAV `409 Conflict`가 발생하고 캐시는
보존됐다. 상위 폴더 자동 생성 여부와 프로토콜 오류 본문 요약은 후속 결정 대상으로
남긴다.

### 9. 캐시 용량과 보존 정책

- 전체·프로필별 캐시 사용량과 보존 항목 수를 표시한다.
- 정상 완료된 임시 파일과 복구가 필요한 보존 파일을 구분한다.
- 복구 항목은 기본적으로 자동 삭제하지 않는다.
- 용량 한도와 보존 기간은 미리보기와 사용자 확인이 가능한 뒤 도입한다.

기본 용량, 보존 기간과 경고 임계값은 실제 사용량을 확인한 후 결정하며 이 계획에서
임의의 기본값을 정하지 않는다.

2026-09-01 전체 캐시 바이트, 복구 목록의 항목 수·스테이징 바이트,
메타데이터 없는 항목과 프로필별 보존 사용량 집계를 구현했다. 디렉터리와 심볼릭
링크는 용량 합계에서 제외하고 메타데이터 파일 크기는 전체 캐시 바이트에만 포함한다.
자동 삭제·용량 제한·경고는 여전히 실제 Windows 사용량 확인과 정책 결정 전에는
실행하지 않는다.

## 0.6C — 연결 상태와 진단

- 프로필 상태를 `연결 안 됨`, `연결 중`, `연결됨`, `해제 중`, `오류`로 구분한다.
- 마지막 오류와 발생 시각, 보존 캐시 수를 프로필 상세에서 확인할 수 있게 한다.
- 열린 파일 핸들 수를 안전하게 얻을 수 있는 경우 일반 해제 차단 안내에 함께 표시한다.
- 지속적인 네트워크 폴링은 추가하지 않고 실제 연결·파일 작업 결과를 상태 근거로
  사용한다.
- 전송 진행률과 취소는 백엔드별 안전한 중단 방법을 검토한 뒤 후속 범위로 둔다.

2026-09-01 연결 실패는 프로필 상태를 `오류`로 남기되 드라이브 문자를 예약하지 않아
즉시 재시도·설정 변경·프로필 삭제가 가능하게 했다. 마지막 연결/해제 오류와 발생
시각은 프로필을 선택했을 때 상태 영역에 표시하며, 성공한 재연결·해제 뒤에는 이전
오류를 지운다. 프로필별 보존 캐시 수와 바이트도 같은 영역에 표시한다.

2026-09-02 Windows 실환경에서 연결 실패 상태·마지막 오류·발생 시각, 오류 뒤 재시도와
성공 시 이전 오류 제거, 전체·프로필별 캐시 사용량 표시를 확인했다.

## 0.7 — 배포 준비

- 실행 파일의 Windows 파일 아이콘, 제품명, 파일 버전 정보를 넣는다.
- 버전 문자열의 단일 기준과 재현 가능한 Windows 빌드 절차를 마련한다.
- WinFsp 요구 버전, 설치·삭제, 설정·캐시 위치와 복구 절차를 사용자 문서에 정리한다.
- ZIP 배포물과 체크섬을 우선 제공한다.
- 설치 관리자, 코드 서명과 자동 업데이트는 별도 결정 후 범위를 확정한다.

릴리스 전 필수 확인:

- 실제 Windows 로그아웃·로그인 후 트레이 자동 실행과 자동 연결
- 격리된 테스트 파일로 업로드 실패, 캐시 보존, 로컬 내보내기
- 일반 해제 취소와 강제 해제의 데이터 보존 안내
- Implicit FTPS 실서버 검증 또는 릴리스에서 실험 기능으로 명시
- 대표 프로토콜 공통 GUI 회귀와 프로토콜별 연결·읽기 스모크

## 후속 호환성 범위

다음 항목은 제품화 필수 단계와 분리한다.

- WebDAV 서버가 지원하는 경우 수정 시간과 파일별 ReadOnly 처리
- Hidden, System, Archive 등 Windows 속성 매핑 정책
- 장시간 단절과 전송 중 단절 복구
- 백엔드가 안전하게 지원하는 경우에 한한 전송 재개

## 테스트 기록 규칙

- 공통 데스크톱 동작은 [데스크톱 검증 체크리스트](desktop-validation.md)에 기록한다.
- 프로토콜 고유 동작은 각 연결 기술 검증 문서에 기록한다.
- 자동 테스트 통과만으로 실제 Windows/NAS 항목을 완료 처리하지 않는다.
- 미지원 서버 기능은 실패로 숨기지 않고 제한 사항 또는 실험 기능으로 명시한다.

## 구현 전 결정이 필요한 항목

다음 값과 정책은 관련 단계에 도달했을 때 실제 사용 결과를 근거로 결정한다.

- 캐시 용량 한도, 보존 기간과 경고 시점
- 원격 충돌 비교 기준과 서버 메타데이터가 부족할 때의 기본 선택
- 설치 관리자, 코드 서명과 자동 업데이트 제공 여부
